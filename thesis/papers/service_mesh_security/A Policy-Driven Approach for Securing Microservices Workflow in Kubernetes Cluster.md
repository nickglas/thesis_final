A Policy-Driven Approach for Securing Microservices Workflow in Kubernetes Cluster  Bilal Ashraf, Satish Kumar, Nawar Jawad  School of Built Environment, Engineering and Computing Leeds Beckett University, Leeds UK  b.ashraf2495@student.leedsbeckett.ac.uk, s.kumar, n.jawad@leedsbeckett.ac.uk  Abstract —Kubernetes   based   microservices   deployments   are increasingly adopted in modern cloud computing environments. However, securing microservices in Kubernetes cluster is critical because they operate in distributed manner across different nodes and each of which gives a potential entry point for attackers due to weak authentication mechanism or misconfiguration of security policies. To address these issues, we propose two layered policy-driven   security   mechanism   for   securing   microservices workflow in Kubernetes cluster. The first layer employs mutual TLS (mTLS) for secure service-to-service authentication using the Istio service mesh. The second layer introduces workflow-based authorization policy enforced through Open Policy Agent (OPA) Gatekeeper. Experimental results demonstrate that unauthorized access is effectively blocked at the entry point, confirming that the proposed approach establishes a robust, multi-layered security environment for Kubernetes-based microservices.  I. I NTRODUCTION  The modern microservices application runs in distributed fashion across different nodes in Kubernetes Cluster 1 , typi- cally built on top of virtual machines (nodes) in cloud data centre. The Kubernetes security by default is liberal unless properly configured, where each microservice in the cluster can communicate with other microservices without restric- tions which expose vulnerabilities and potential entry point for the attackers to compromise one microservice (Pod) and gain access to the entire application running in cluster [1]. Therefore,   securing   microservices   in   a   Kubernetes   cluster is essential, specifically to implement security measures at individual microservice level. Kubernetes offers built-in se- curity measures such as Role-Based Access Control (RBAC), network policies and Pod Security Policies. However, RBAC only manage end-user authentication, specifically who can access the resources (microservices) in the cluster, yet does not control how microservices securely communicate with each other after deployment [2]. This insecure microservice- to-microservice communication increases the chances for at- tackers to succeed. Therefore, it is important to ensure that a microservice authenticates any microservices it interacts with during operation, trusting them only after they present a verifiable identity document [3]. To address above issues, we employ Istio Service Mesh that provides built-in secure service-to-service communication. As shown in Figure 1, the integration of OPA with Istio Ser- vice Mesh can be used as an authentication service to enforce security policies over microservice requests received by Istio sidecar proxy [4]. Aforementioned, Istio secure the runtime layer by managing microservice-to-microservice authentica- tion (mTLS) and traffic encryption, while OPA Gatekeeper operates at admission control level for enforcing cluster wide policies for resources (microservice) validation. C ONCLUSIONS  Kubernetes-based microservices face critical security risks due to distributed deployment and weak authentication. To address this, we propose a two-layered secure authentication by implementing Istio mTLS for secure service communica- tion and OPA Gatekeeper for workflow-based authorization.

I   NTRODUCTION  N OWADAYS, intelligent services based on deep learning (DL) are becoming more popular with the development of artificial intelligence (AI) and communication technology. As one of the main deep neural networks (DNNs), convolutional neural networks (CNNs) are widely used in vision applications such as object detection, object classification, and visual re- ality [1], [2], [3]. Considering the relatively less computing resources, little storage space and limited power of end devices and edge servers [4], it is difficult to deploy and infer a whole CNN model with large parameter quantity and computation amount completely with high efficiency on an edge device [5], [6]. One traditional solution to the problem is to offload the inference task of the CNN to the cloud server. With so strong computing power, the cloud server is able to infer a large CNN model with low latency and improve quality of intelligent services (QoSs). However, the long distance between edge and cloud causes huge transmission latency of raw input data from intelligent ser- vice customers [7]. Too large data transmission latency signif- icantly increases the total response time of intelligent services and reduces the QoS. Furthermore, traditional cloud computing brings large security risk to customers’ privacy. Specifically, remote location of the cloud server causes prolonged exposure of customers’ privacy data in the process of transmission, which largely increases the possibility for customers’ privacy to be stolen. Also, the centralized and outsourcing pattern of cloud computing make customers’ data stored on the cloud easier to be visited and attacked by third-party attackers [8]. Distributed inference for CNNs on various devices is an excellent method to improve inference efficiency and reduce inference latency 2691-4581 © 2024 IEEE. In detail, existing work has proved that the size of most intermediate output from CNNs is smaller than that of raw input from users [10]. So a CNN model can be partitioned into two or more parts, the shadow ones with lower computing intensity deployed at edge and the deep ones with higher computing intensity deployed on the cloud. This distributed inference pattern is called model partition. In model partition, data transmission latency is reduced for smaller trans- mission size, and computing intensive layers are still inferred efficiently on the cloud. Besides model partition, there is an- other distributed inference pattern called model parallelism. In model parallelism, each layer of a DNN is split into several parts, which are inferred on different devices in parallel. Model parallelism breaks through the layer-by-layer inference pattern of model partition, thus further reducing computing latency of each layer. But more data transmission latency may be caused by the increasing interaction between different devices and there may exist inference accuracy loss because of the integrity breach for layers in model parallelism. Besides response time, privacy protection is also attracting more attention with popularization of intelligent services [11], which facilitates researching on the reliable AI system. In a reliable AI system, the response time of services should be minimized to improve customers’ experiment while protecting customers’ privacy from being attacked and stolen [12], in order to make the services trusted by humans. Depending on the in- formation of DNN models which can be achieved by attackers, there are two kinds of attack during DNN inference process, which are white-box attack and black-box attack [13], [14]. In white-box attack, the parameters of DNN models are known by attackers and they can query inference of DNNs deployed in servers. In black-box attack, attackers can only access the input and output of DNNs deployed in servers without getting the internal parameters. Considering great attention paid by service providers to protecting customers’ privacy, white-box attack is rare in reality. Besides, former work mainly studies how to protect customers’ privacy without considering a distributed system. So how to effectively protect customers’ privacy from black-box attack during distributed inference process is worth studying. It should be emphasized that split and partition are two different concepts in this article, which cannot be confused. In detail, split is an operation cutting a layer into several parts to achieve model parallelism, while partition cuts a complete DNN model into several parts and each layer of the DNN is inferred completely without split. To overcome the above mentioned challenges, in this article, we design a CNN distributed inference system which joins model partition and model parallelism together. We put each service request in a distributed inference system into a corre- sponding queue according to its priority. Then, we split each convolution layer (conv) into several parts which are inferred in parallel on different edge servers for inference latency reduc- tion. At last, we find a proper partition point to achieve edge– cloud collaborative CNN inference for further latency reduction while decreasing the possibility for customers’ privacy to be stolen. Compared to former work, two challenges are tackled in this article. First, the inference latency of CNN can be further re- duced. Second, privacy protection should be considered during distributed inference process of CNN. The main contributions of this article are as follows. 1)   An optimized queue mechanism is designed in this article to ensure the minimal response time of services with the highest priorities while reducing waiting time of services with relatively low priorities as much as possible. 2)   A deep reinforcement learning (DRL)-based CNN par- allelism   method   is   proposed   to   shorten   CNN   infer- ence latency. 3)   A brute force algorithm-based CNN partition method is proposed to further decrease CNN inference latency while protecting customers’ privacy. 4)   The effectiveness of the proposed method is confirmed by the comparative experiments. Devices with limited computing power at edge are hard to infer a complete DNN model in a short time for the intensive computation of DNNs. [19] proposed a complete framework to jointly optimize DNN partition, target server selection and computing resource allo- cation based on Max-Flow/Min-Cut algorithm and generalized assignment problem in a scenario with multiple end devices and edge servers. Novel Queue Mechanism  We assume that there are only a few kinds of CNNs possible to be used in a distributed inference system, and services based on the same kind of CNN are sequentially and alternately pro- cessed using a novel queue mechanism. The workflow of the novel queue mechanism is shown in Fig. 3. First, the allocation of computing resources for each service request in each edge server is presented in the left part of Fig. 3. Specifically, the process of resource allocation consists of two steps. In step one, computing resources in each edge server are grouped for each kind of CNN according to its proportion of floating-point operations (FLOPs) among all CNN models. In step two, in terms of the computing resources allocated to a certain kind of CNN, they are further grouped for each conv of the CNN according to the proportion of FLOPs of each conv among the CNN. Note that the allocation of computing resources is conducted offline and the resource allocation decisions will not change in the future. Besides, the number of resources allocated to each conv of a certain kind of CNN will not be used to infer other convs. After resource allocation, the details of sequen- tial and alternate task process are shown in the right part of Fig. 3. For ease of understanding, we explain this process using an example. We assume that there are three service requests with different priorities, which reflect the latency sensitive of different tasks, based on the same kind of CNN, and they are successively put into a queue according to their priorities. In the beginning, the various parts of the first conv (conv1) of the task with the highest priority (task1) are inferred in parallel on different edge servers. When the inference of conv1 of task1 is finished, the second conv (conv2) of task1 begins to be inferred. Meanwhile, the conv1 of task with the middling priority (task2) is also inferred. Next, conv1 of task with the lowest priority (task3), conv2 of tasks and the third conv (conv3) of task1 are simultaneously inferred on the edge servers in parallel. For each task, the process of parallel conv inference continues until the convs, decided to be inferred at edge, of that task are all inferred, and the aggregated intermediate feature map will be sent to the cloud for further inference. It is obvious that from the macroscopic angle, tasks with different priorities are inferred one by one, which conforms to the characteristic of sequential task process. From the microcosmic angle, although all tasks in a queue are not able to be processed simultaneously in an absolute sense, the   j th conv of the   n th task and the   ( j   +   1 ) th conv of the   ( n   +   1 ) th task can be inferred at the same time. This characteristic of “not completely simultaneous process of multiple tasks” is named as “alternate process of tasks” in this article. In addition, it should be emphasized that different queues are independent of each other and tasks in different queues are processed simultaneously.  D. M   ETHOD   D   ESIGN In this section, we present details on design of the CNN distributed inference system. Specifically, we solve the original multiobjective optimization problem in two steps. First, we find the decision of conv split for model parallelism at edge using an algorithm based on DRL. Then, we search the model partition point for edge–cloud collaborative inference using brute force algorithm. Fig. 4 illustrates the architecture of our CNN distributed inference system. A. CNN Parallelism at Edge  At first, for a certain type of CNN model, we make decisions for split of each conv in it. As mentioned above, a certain group of computing resources in an edge server is only used to infer a certain conv of a CNN model and the number of resources inferring a certain conv is fixed and known.
